# DECISIONS

One line per under-determined choice (SPEC §12): decision + why + affected module.



- **P0** Python 3.12.13 via uv-managed interpreter (`uv venv --python 3.12`); system Python is 3.11 — spec requires 3.12. Affects: dev environment only.
- **P0** No `pydantic-settings` dependency: SPEC §3's dependency list is exhaustive and does not include it, so `Settings` is a plain pydantic model with a small YAML+env loader. Affects: `context.py`.
- **P0** IR nodes are frozen stdlib dataclasses, not pydantic — §6.2 calls them IR dataclasses; pydantic reserved for facts/values/records/config per §3. Affects: `ir/nodes.py`.
- **P0** IR keeps `FuncDefS`/`ClassDefS` statement wrappers (so nesting is visible for wrapper/agent-shape anchoring) and models `BoolOpE`/`UnaryOpE` (loop guards like `while not done and turns < N` must stay analysable for F5); everything else lowers to Opaque. Affects: `ir/nodes.py`, `parse/py_ast.py`.
- **P0** `match` statements lower to an `IfS` chain with opaque tests, per §6.2. Affects: `parse/py_ast.py`.
- **P0** Secret redaction (a P2 §6.5 item) implemented at P0 because it must live at IR-lowering time before any persistence; patterns are exactly the §6.5 shapes. Affects: `parse/py_ast.py`.
- **P0** `--commit` on a *local path* target is recorded but never checked out (checkout would mutate the user's working tree, violating read-only ingestion); a warning is logged. Affects: `ingest/git.py`.
- **P0** Imports inside function bodies are recorded in the module's import list (over-approximation consistent with ADG semantics). Affects: `parse/py_ast.py`.
- **P0** `ValueRepr` of a multi-value set is `{"union": [reprs...]}` in deterministic order; spec only defines the single-value projections. Affects: `ir/values.py`.
- **P0** Lockfile version lookup covers `requirements*.txt` (`==` pins), `poetry.lock`, `uv.lock` (both TOML, parsed with stdlib `tomllib` — no new dependency); import-name→distribution-name mapping is exact-match only. Affects: `modules/graph.py`.

- **P1** `boto3.client("bedrock-runtime")` resolves to `ClassInstance("boto3.bedrock-runtime-client")` matching the SPEC §6.5 registry root spelling. Affects: `resolve/engine.py`.
- **P2** Known-host sinks get confidence "high" (host identity is strong evidence even when the payload is opaque); spec fixes confidence only for shape sinks. Affects: `sinks/engine.py`.
- **P2** Sinks in class-method bodies resolve with `self` unbound at definition site — model shows as unresolved there; per-call-site attribution through the wrapper is P5's fixed point. Affects: `sinks/engine.py`.

## SPEC-2 (scope: enrichment only, per user direction)

- **Scope** Per user direction, SPEC-2 is built as **enrichment only** — SPEC-1's record schema holds; the derived-indicator engine (§5), full governance/external field catalogue (§3), dataset (§6) and fleet runner (§7) are **not** built. Only the `[E]` summary fields and the enrichment layer (§4) are added. Affects: `inventory/schema.py`, `enrich/`.
- **LLM sharing** The OpenAI-compatible provider (SPEC-1 P7) is factored into `aiscan/llm.py` and shared by **both** LLM tiers: adjudication (resolves *detection* ambiguity) and enrichment (drafts *descriptions*). Both read the same `.env` credentials; `build_openai_call_fn` takes a `schema_hint` so each tier binds its own output schema. Affects: `llm.py`, `adjudicate/providers.py`, `enrich/engine.py`.
- **Schema** `EnrichedSlot` gains `confirmed_by` (null until a human signs off) and `insufficient_evidence` (reason when grounded=false). `[E]` fields added: system (`system_summary`, `capability_summary`, `data_interaction_summary`, `human_oversight_summary`, `suggested_aia_risk_category`), agent (`agent_summary`, `responsibilities`, `guardrails_summary`), tool (`tool_summary`, `capability_class`, `data_domain`), mcp (`server_summary`); all default null. Findings stay SPEC-1 `FindingRecord` (no severity/subject_ref split — that was out of scope). Affects: `inventory/schema.py`.
- **One call per node** SPEC-2 §4.2 returns one summary per node, but the system has four summary fields; rather than multiple calls per node (§4.5 forbids), the system node's response contract carries the extra summaries in one call. Affects: `enrich/schema.py`, `enrich/engine.py`.
- **Anti-hallucination** `grounded=false` writes `{value: null, insufficient_evidence: reason}` — never a fabrication. The code slice is re-scrubbed for secrets (via the adjudication slicer) and framed as data-not-instructions in the system prompt (prompt-injection corpus test). Classifications land as `[E]` candidate values only; enrichment never writes [G]/[X] or overrides [D]. Affects: `enrich/engine.py`.
- **Off-path & determinism** `--enrich` is off by default; with it off the record is byte-identical (all `[E]` slots null) so the goldens compare detected output only. Enrichment runs after emission, is cached by node content hash (`enrichment_cache.json`), batched over a small thread pool, and a missing key / failed call degrades to null `[E]` + a `scan_health.enrichment` note rather than crashing. Reuses the `AISCAN_ADJUDICATE_*` endpoint/model settings (one LLM config). Affects: `cli.py`, `enrich/engine.py`, `context.py`.

## SPEC-3

- **V0** `ai_verdict` computed in `build_record` (agents/usages/MCP/sink-count > 0 → `ai_detected`; MCP counts as detected — a declared server is AI usage even with zero code sinks). `no_ai_detected` kept as a derived back-compat bool. `ScanHealth.adjudication` added so both LLM tiers report status symmetrically; the no_ai LLM guard writes `{status: skipped, reason: no_ai verdict}` for any tier whose flag was on. Goldens re-blessed at V0 (verdict + adjudication field) and again at V1 (derived fields) — SPEC-3 §10's "once" became once-per-schema-phase. Affects: `inventory/schema.py`, `inventory/emit.py`, `context.py`, `cli.py`.

- **V1** Derive engine works over the emitted `Record` (not the graph): every input it needs (tools' side-effects/targets, handoffs, policies, locations, endpoints) is already record-surfaced, keeping it a pure `(record, org_pack, host_registry) → record` function. Two record additions to make that true: `AgentRecord.routes` (route-transfer targets — also needed for the V4 graph) and `ModelUsage.endpoint` (provider_class input). `provider_class` rule: endpoint `None` → `vendor_external` (SDK default host); literal host → gateway/vendor/private-IP classify; symbolic/template → `unknown`, never guessed. `moves_money` requires the new optional org-pack `payment_hosts` key. `high_privilege_agent` fires for production/example agents only. Invoke-kind transfers stay unsurfaced (no corpus construct). `scan_health.findings` recount happens in derive since it appends findings post-emit. Affects: `derive/engine.py`, `inventory/schema.py`, `inventory/emit.py`, `facts/models.py`, `context.py`, `cli.py`.

- **V2** AI-BOM rows come from the triage `manifest_ai_package` signals (path:pkg pairs) + org wrapper roots that are actually imported; `used` matches normalised package name against top-level import roots, exact-match only (consistent with the P0 import→distribution mapping decision — `google-generativeai` imported as `google.generativeai` shows `used: false`; acceptable, honest). `candidate` moved onto the base `GovernanceSlot` (E→G mechanism, SPEC-3 §4.3); `OwnerSlot` stays as a named subclass. Resolver stubs in `inventory/resolvers.py` return `Unresolved(reason="not_wired")` — nothing wired. Third schema-phase golden bless. Affects: `inventory/bom.py`, `inventory/schema.py`, `inventory/resolvers.py`, `inventory/emit.py`, `cli.py`.

- **V3** `report.html` is generated in `write_artifacts` on every scan, stdlib-only (string building + `html.escape`; no jinja2). Deliberately never renders `stage_ms` and shows only the org-pack basename, so the report is deterministic modulo the record's own `scanned_at` (normalised in goldens by regex, same treatment as record.json). Report goldens: flagship + framework + negative page (`REPORT_FIXTURES`). The `adversarial_html_escape` fixture uses the local-package re-export trick (like the monorepo test) plus an `openai-agents` requirement so triage fires; payloads sit in agent name/prompt/model and must never appear unescaped. Affects: `report/html.py`, `inventory/emit.py`, `tests/harness.py`, `tests/test_report.py`.

- **V4** Graph SVG is built from the *record* (agents/tools/MCP/models + handoff/route fields), not graph.json — everything the view needs is record-surfaced and it keeps `render_graph_svg` a pure function usable by enrich-in-place. Columns system→agents→tools+MCP→models; same-column handoff/route arcs; location shown as border dash. Scale guards: >20 agents per location → one aggregate node; 150-node cap collapses test→example→production; legend always prints shown/total (no silent truncation). Rendered only on `ai_detected`. Affects: `report/graph_svg.py`, `inventory/emit.py`.

- **V5** Enrichment planning is location-ranked (system → production → example → test-only-with-flag); a tool/MCP inherits the best location of any binding agent, unbound components rank as production. E→G candidates land only from a *grounded* system response and never overwrite a human-set `value`. Enrich-in-place triggers when the CLI target contains `record.json` (requires `--enrich`); without `--repo` it degrades to facts-only grounding, recorded as `scan_health.enrichment.grounding = facts_only`; only record.json/scan_health.json/report.html are rewritten (`write_record_artifacts`). Affects: `enrich/engine.py`, `enrich/schema.py`, `inventory/emit.py`, `cli.py`.

- **V6** `flatten` works on the record.json *dict* (not the pydantic model) so the dataset is rebuildable from any on-disk records regardless of scanner version — missing fields flatten to null. Complex cells (side_effects, endpoints) are canonical-JSON strings. Rebuild identity gate = ordered SELECT dumps + byte-identical CSVs (the sqlite file itself may differ byte-wise). `models` rows come from the derived `models_used` (distinct models with provider_class), not per-usage rows. Affects: `dataset/flatten.py`, `dataset/store.py`, `dataset/queries.py`, `cli.py`.

- **V7** Fleet scans run **sequentially** in input order (SPEC-3 §9.1 said "default 2" concurrency; the shared wrapper-registry file is read-modify-write per scan, and parallel writes would race/drop entries — determinism and registry integrity win; parallel fleet is a later optimisation behind a proper registry lock). Each target scans into an indexed slot `records/NNN-<basename>/` because two repos may share a basename (every fixture is literally named "repo"). Estate `index.html` is built from the records (not the DB) and carries the same CSP/escaping discipline; `fleet_summary.json` is the machine-readable run summary. Affects: `fleet/runner.py`, `cli.py`.

- **Coverage honesty (DocGen case)** A real scan of a TypeScript monorepo (62 .ts/23 .tsx, one incidental .py) reported "ai_signals_only" with no hint that the actual LLM code was outside the Python-only analysis — false comfort. Fixes: (1) language census (`count_source_files`, extensions only) into `scan_health.language_files` on every scan; (2) npm AI packages matched against package.json dependency *keys* (safe for `ai`, the Vercel SDK) → new triage signal `manifest_ai_package_js` — so a pure-TS AI repo can never exit `no_ai` — and AI-BOM rows with `ecosystem: "npm"` rendered "outside Python-only analysis", never "dormant"; (3) `unanalysed_language_code` finding (medium when AI signals present, info otherwise); (4) a prominent "Partial coverage" report banner under the header. Verified on DocGen: banner + medium finding + `openai@npm` BOM row. Affects: `ingest/triage.py`, `context.py`, `inventory/schema.py`, `inventory/bom.py`, `derive/engine.py`, `report/html.py`, `cli.py`.

## SPEC-4

- **W0 — GO.** tree-sitter wheels (`tree-sitter==0.26.0`, `tree-sitter-typescript==0.23.2`, `tree-sitter-javascript==0.25.0`) resolve and install cleanly on win/py3.12; pinned exactly in pyproject — grammar upgrades shift spans (and goldens) so they are deliberate, blessed events. Justified as SPEC-1's sanctioned "tree-sitter is a v1 swap" dependency. Affects: `pyproject.toml`.
- **W0** Lowering choices beyond the SPEC-4 §2.1 table: ternary `c ? a : b` lowers to `BoolOpE("either", (a, b))` and `??` to `BoolOpE("or", …)` — resolved by the SPEC-5 X0 BoolOp union rule (guard dropped, matching ADG over-approximation; Python's `IfExp` stays Opaque, unchanged). *Correction note: as originally written this line claimed the resolver already unioned BoolOp operands — no `BoolOpE` case existed until SPEC-5 X0; the DocGen `env || literal` models resolved to `Top("dynamic")` because of it.* `this` lowers to `NameE("this")` and constructors keep the name `constructor` — W2 teaches the resolver's ctor-attr rule both conventions rather than faking `self`/`__init__`. `require()` in a declarator lowers to ImportIR (identifier → module binding; destructured → from-import). `export default <expr>` binds local name `default`. tree-sitter error recovery: files with ERROR nodes still lower (broken subtrees → Opaque) — only an unparseable root yields ParseErrorInfo, maximising recall. `ModuleIR.exports` added (additive) for W1 barrel canonicalisation; Python modules leave it empty. Block-bodied inline arrows (object-property callbacks) are Opaque until W4 needs them. Affects: `parse/ts_tree_sitter.py`, `ir/nodes.py`.
- **W0** `parse/registry.py` owns extension→backend and two sets: `PARSEABLE_EXTS` (backends exist) vs `PIPELINE_EXTS` (census/banner basis, still `.py` only) — the pipeline set flips at W6 when TS flows through detection end-to-end; flipping earlier would silence the partial-coverage banner before coverage is real. Affects: `parse/registry.py`.

- **W1** Cross-language identity is **dot-joined** `"<specifier>.<export>"` (`openai.default`, `@openai/agents.Agent`) — a deliberate deviation from SPEC-4 §3's `:` proposal, because dot-join is what the existing resolver already produces for `SymbolImport` bindings (zero forks; §12 ambiguity protocol). TS module names are repo-relative paths without extension (dot-free, so `fq.split('.')` stays clean). Import-specifier resolution happens at symbol-table build time (`ModuleGraph._remap_ts_imports`): resolved → internal module name; unresolved → raw specifier → external `PackageRef` downstream. Barrel re-exports chase through the existing `_module_member` import-following — proven end-to-end (ClassRef `src/core/agent.Agent` through a barrel). tsconfig parsing strips `//` comments + trailing commas; npm versions from package-lock.json + a best-effort pnpm-lock line regex; package.json version *ranges* are never used as pins. Affects: `modules/ts_graph.py`, `modules/graph.py`.

- **W2** All resolver additions are language-parametric (no `if typescript`): `process.env`/`import.meta.env` recognised by dotted name → a shared `process.env` env-sentinel PackageRef, reusing the existing `os.environ` subscript/attr paths → `Symbolic(env)`; `import.meta` lowers to `AttrE(NameE("import"),"meta")` so the chain has a dotted name. `JSON.stringify(x)` unwraps to `x` (payload-through). The receiver binding now covers both names — `env["self"]` **and** `env["this"]` point at the instance; `_instance_attr` accepts `constructor` alongside `__init__` and `this.x=`/`self.x=` alike. Standalone `this` in a method body stays unbound (same as Python `self` — the P2 decision; wrapper fixed point resolves it per-call-site at W5). List-growth folding extended from `append`/`extend` to `push` (multi-arg), feeding F4 message-state detection. Affects: `resolve/engine.py`, `parse/ts_tree_sitter.py`.

- **W3** SDK-sink registry gains TS roots (dot-joined identity, W1) — the scoring/attribution engine is untouched. Two extraction shims make JS call conventions work through the *same* engine: `_named_arg` reads `create({ model })` (single options object) as well as `create(model=...)` (Python kwargs); `_ctor_kwarg_vals` reads `new OpenAI({ baseURL })` as well as `OpenAI(base_url=...)`. HTTP shape sinks: `_ts_http_inputs` extracts (url, payload, headers) from fetch/axios/got — fetch's payload is nested in `options.body`, unwrapped via the W2 `JSON.stringify` pass; the endpoint-agnostic scorer + host logic + azure-deployment split then run identically (azure split needed **zero** new code — proven: `prod-gpt4` deployment extracted from a TS fetch URL). Response-signal strings (`choices[0]`, `finish_reason`) are identical in TS, so `_response_fields` works unchanged. Affects: `sinks/sdk_registry.yaml`, `sinks/engine.py`.

- **W4** Three JS packs (`openai_agents_js`, `langgraph_js`, `vercel_ai`) — data only; the rule engine is unchanged bar one shared shim: `_arg_expr`/`_agent_name_from_instance`/`_extract_model` now read a single JS options-object argument (`new Agent({ name, tools })`) as well as Python kwargs, via `_ctor_arg`/the object-member fallback (Python kwargs still match first, so Python behaviour is untouched). Affects: `sinks/engine.py`, `frontends/bespoke/agent_shape.py`, `adjudicate/engine.py`.

The org wrapper registry is written only by full scans (incremental sees a subset; affected modules read the full classification set from it). Affects: `frontends/framework/engine.py`, `inventory/emit.py`, `incremental/factcache.py`, `cli.py`.
- **I3 (the equivalence guarantee)** `tests/test_incremental.py` is the load-bearing proof: for a battery of diffs (change model, add tool, add agent, unrelated file, cross-module handoff, cross-module entrypoint move, prompt change, source deletion→escalate) it asserts `incremental(base→head)` produces the **byte-identical record + graph** as a from-scratch `--full` scan of head (scan_health excluded — sink/resolver counters reflect only the re-analysed slice; `facts.jsonl` not compared — it may differ in fields the BOM never consumes). `ANALYSIS_VERSION` gates the whole cache: any change to analysis logic must bump it, which forces full rescans until re-seeded — a cached fact never outlives its detector. Recommended operationally: a periodic full scan even under CI-incremental, so any latent drift self-heals. Deferred: multiprocessing across module clusters (orthogonal ~5–6× win). Affects: `tests/test_incremental.py`, `incremental/gate.py`.

## Framework breadth

- **F0 (agnostic core + first-class packs)** The detector is framework-agnostic by design — the bespoke frontend (F2) finds hand-rolled agents by *shape* (an LLM sink in a loop that branches on the response) and the sink layer is endpoint-agnostic. Framework packs (F1) are an additive *precision* layer: for framework agents the LLM call is hidden inside the library (user code only does `AssistantAgent(model_client=…)`), so no sink is visible to F2 — the pack is what makes them detectable, with clean name/model/tools/handoffs. Added packs for **PydanticAI, LlamaIndex, AutoGen (v0.4 AgentChat + v0.2 legacy), Semantic Kernel**, matched on resolved public import identity (consumer repos) canonicalised to the definition module (monorepos). Triage recognises `pydantic_ai` and `autogen_agentchat`/`autogen_ext` (the `autogen\b` regex missed the underscore forms). Known follow-ups: AutoGen/Swarm **name-string handoffs** (`handoffs=['beta']`) inventory both agents but not the transfer edge (instance handoffs do emit it); AutoGen v0.2 model lives in an `llm_config` dict (agent+prompt detected, model unresolved). Affects: `frontends/framework/packs/{pydantic_ai,llama_index,autogen,semantic_kernel}.yaml`, `frontends/framework/engine.py`, `ingest/triage.py`, `tests/test_framework_packs.py`.

## SPEC-9 (update-resilient detection & lean-up)

- **A1 (kwarg-drift resilience, data-only)** Agent-ctor rules in the four added packs list kwarg alternates via the SPEC-8 arg-list DSL (`model: {arg: [1, model_client, model, llm]}`, `instructions: {arg: [system_message, system_prompt, instructions]}`, `tools: {arg: [tools, plugins, functions]}`) with the framework's real kwarg first (behaviour preserved) — a renamed kwarg no longer blanks a field, zero code. Bare `client` excluded from model alternates (ambiguous vs an HTTP client). Affects: `frontends/framework/packs/{autogen,pydantic_ai,llama_index,semantic_kernel}.yaml`.
- **A2 (agnostic agent-ctor fallback, anchored on a resolved model)** A ~40-line `FrameworkEngine._match_agent_ctor`, run from the existing `_run_call_rules` per-site loop *only when no pack claimed the site* (the F1-exclusion, free) — no new pass, no new module, reusing `_extract`/`_extract_model`/`_extract_refs`/`_agent_id`. Emits `AgentDefF(confidence="medium", method="agent_shape:ctor", kind="bespoke")`. Four gates, none using the class name (the "resolved identity, never surface text" premise): (1) a cheap syntactic prefilter — an agent-shaped companion kwarg name present (tools/instructions/system/…); (2) the callee's `chain_root` base is not a `ClassInstance` — an agent is a class *construction*, never a method call on an instance (`client.messages.create(model=…, system=…)` is a raw sink, excluded here); (3) a model *resolves* AND `_is_model_value` says it looks like a model — a model-adapter instance (a class carrying a model kwarg) or a string matching a known model family / provider-prefixed model — which rejects `model=SchemaV2` (class ref) and `name='Researcher'` (plain string); (4) the model kwarg may be named (model|llm|model_client|service|chat_model) *or* found by value on any other kwarg (name-independent, so a renamed model kwarg like `engine=LlmClient(model=…)` is still caught); plus an agent-shaped companion that actually resolves (a bare model call is a sink, not an agent). Survives class rename, module move, kwarg rename, and unknown frameworks; packs still win (high confidence, no double-emit — the fallback only sees unclaimed sites). Verified: `test_agnostic_agent.py` (rename/move + unknown-framework positives at medium; local `Agent(name, schedule)`, non-AI `ReportAgent(model=SchemaV2, client=S3Client())`, and a bare model call all rejected; pack wins). No existing golden changed except resolver diagnostic counters (A2's `chain_root` on unclaimed companion-bearing sites). Affects: `frontends/framework/engine.py`, `tests/test_agnostic_agent.py`.
- **B (verified lean-up)** Adversarial subsystem audit (12-agent workflow) returned 15 byte-safe simplifications; applied the clean/high-value ones: dead `Scope.click_params` branch (unreachable — every click param already lands in `env`) and its field; dead `_single_of` (sinks); the byte-identical `_ctor_arg`/`_ctor_kwarg_vals` duplicate hoisted to one `ctor_kwarg` in the sinks layer (framework imports sinks, not the reverse — avoids an import cycle); `provider_class` reused from the derived usage instead of recomputed; SPEC-8's own cruft — the dead `modules_by_name` param threaded through `incremental/depgraph.py`, and the location-grouping loop duplicated between `_agents_section`/`_tools_section` extracted to `_by_location`; soft-qualifier-chip rendering (3×) to `_soft_chips`. Affects: `resolve/engine.py`, `sinks/engine.py`, `frontends/framework/engine.py`, `derive/engine.py`, `incremental/depgraph.py`, `report/inventory.py`, `cli.py`.

## SPEC-10 (scalability seams: embeddable core, pluggable source & storage)

Groundwork for a future GitHub-connected, PR-triggered, ephemeral-clone, multi-repo service — built as clean **seams behind byte-identical defaults**, with NO service/infra (no Docker, DB server, queue, webhooks). Every change is gated on the existing byte-identical golden + SPEC-8 incremental-equivalence suites (no re-bless anywhere). An 8-reader + synthesis + adversarial-critique workflow produced the plan; the critique caught two load-bearing corrections folded in below.

- **5a (determinism-on-write)** `record.json` as physically written was NOT byte-stable — `emit.py` stamped a wall-clock `scanned_at`, wall-clock `scan_health.stage_ms`, and an absolute `org_pack` path; the normalisation that makes the goldens match lived ONLY in `tests/harness.py` and never ran on the write path, so two scans of one commit produced different bytes. Fix: a production `inventory/identity.py::identity_record(data)` (the deterministic projection — sentinel `scanned_at`, empty `stage_ms`, basename `org_pack`) that the store hashes for `(repo,commit)` change-detection and the harness now imports (killing the prod/test drift). Human-facing `scanned_at` stays real (non-identity metadata); `org_pack` is written as a basename (removes a determinism break + a multi-tenant path leak). Idempotent ⇒ goldens compare unchanged. Affects: `inventory/identity.py` (new), `inventory/emit.py`, `tests/harness.py`.
- **5b (canonical (repo,commit) identity)** URL bundle name keyed by basename collided across an org (`org-a/api` and `org-b/api` → `api`); now an `owner__repo` slug (`_bundle_name_from_url`, scp/`file://` normalised, host-like owner dropped) — the `repo` half of the `(repo,commit)` key the cache/store use. The wall-clock in the dataset `scan_id_for` is deferred to SOON-K (the write-through upsert is where idempotency bites; dropping it now would collapse the 4-fixture dataset corpus, all `repo:repo|unversioned`, distinguished today only by wall-clock — and the current drop+rebuild model is already stable). Affects: `ingest/git.py`.
- **1 (embeddable core: `core.scan(ScanRequest) -> ScanResult`)** The former `cli._run_pipeline` moved verbatim into `aiscan/core.py`, changing only the terminal step — it RETURNS the live `Record`/`Graph`/fact-lines/analysis-findings/entrypoint-marks it already built instead of `write_artifacts`-ing them and forcing a re-read. `cli.run_scan` is now a thin adapter: it fetches the source, wires the store, calls `core.scan`, persists the result, and renders. The two in-pipeline LLM caches became caller-chosen request paths. No analysis logic changed ⇒ byte-identity untouched; the pipeline is now testable in memory (`tests/test_core_embeddable.py`). `discover_*` helpers moved to core and are re-exported from `cli`. Affects: `core.py` (new), `cli.py`, `inventory/emit.py`.
- **2 (ephemeral SourceProvider)** `ingest/git.py` gained `FetchedSource` + `fetch_source(target, commit, logger)` (a context manager); a URL target is cloned into a temp dir and `rmtree`'d on exit — the persistent `_clones/` reuse model is deleted. The clone is **blobless (`--filter=blob:none`, full history), never `--depth`** — the critique showed a shallow clone truncates the `git log` history `owner.py`/`ai_provenance` derive record fields from, which would break byte-identity vs a full scan. `changed_files` works off full history; a missing base fails safe to full. Verified end-to-end against a local `file://` origin (`tests/test_source_provider.py`). Affects: `ingest/git.py`, `cli.py`.
- **3 (StateStore seam keyed by (repo,commit))** One `aiscan/store.py` protocol — `get/put_manifest`, `has_record`, `get_prior_facts`, `location`, `put_artifacts` — routes the manifest, the incremental fact-cache load, the skip-gate's record check, and artifact writing. `Manifest.scan_out_dir` (an absolute local path) is DROPPED; prior state is addressed by `(bundle, commit)` and the location reconstructed by the store. `should_skip` now takes a `record_present: bool` (the gate is filesystem-free). `LocalDirStore` reproduces today's `<out>/<bundle>-<commit8>/` + `<out>/_cache/<bundle>.json` layout byte-for-byte — a DB/object-store backend is a later swap behind the same protocol. The pure SPEC-8 core (depgraph, gate comparisons, factcache partitioners) is unchanged. Incremental equivalence still holds. Affects: `store.py` (new), `incremental/{manifest,gate}.py`, `core.py`, `cli.py`.
- **4 (no process-global state on the core path)** The core never reads `os.environ`: the LLM key is resolved by the CLI adapter (`resolve_api_key`, after `load_dotenv`) and injected as `ScanRequest.llm_api_key`, threaded to `Adjudicator(api_key=)`/`enrich_record(api_key=)` (env only a fallback for direct callers). Per-scan logger: `_make_logger` builds a standalone `logging.Logger("aiscan")` instance instead of the shared `getLogger("aiscan")` singleton, so two concurrent scans in one process cannot rip out each other's handlers or cross-write `scan.log`. Every pipeline stage already threads `ctx.logger` explicitly. Affects: `cli.py`, `core.py`, `adjudicate/engine.py`, `enrich/engine.py`.
